# Installation and updates

Use the host command executor. Discover Node/npm from PATH; Node 22+ is required. For a published package install `npm install --global @petercjl/photocraft-own` (or an explicitly selected prerelease tag). Verify `photocraft-own version` and the resolved executable before continuing.

Run `photocraft-own install --yes` after the user authorizes installation. `--headless` installs only the native CLI. The package downloads immutable npm payloads, checks sizes and SHA-256, extracts into a new version directory, verifies native executables, then activates its state pointer. Native projects, images and user settings are external to runtime versions. macOS ad-hoc builds may require separate OS trust approval; do not disable OS protections.

Install the canonical Skill with `photocraft-own skill install --agent codex`. For SealSeek resolve its configured Skill root from host context and pass `--agent sealseek --target-root ROOT`. Link/junction is preferred; `--copy` uses verified managed copies. Never guess another Agent’s root. Inspect `skill status --agent ... --json` afterward.

For an authorized update: update the npm package, then run `photocraft-own update install --yes`, update the current Agent’s managed Skill, and run doctor. Global npm installations check stable latest at launch/exec/mcp/serve by default. Development checkouts and non-global installs do not self-update. `update check` is read-only and reports manager and native-program updates separately. Manager and native versions can differ: the manager binds a compatible immutable program release. When its program identity is unchanged, `update install` verifies the installed program and returns unchanged with zero downloads and no activation or state replacement; a running desktop can remain open. An existing headless installation remains headless during updates. A changed program requires the desktop to close before activation. Use `--channel next` only when the user selected prereleases. Existing copied Skills retain user-added files and interface metadata, with backups before replacement. Local edits to managed core files stop synchronization.

`photocraft-own launch` opens the independent desktop. `rollback --yes` switches to a previously verified runtime after authorized recovery; it does not restore edited images. Doctor reports pending transactions and sessions; preserve recovery evidence. Interrupted locks require checking the recorded PID and transaction before a separate recovery decision.

Developer-only local artifacts can be installed with `install --manifest FILE --asset-dir DIR --yes`; this does not represent a registry release.

For SealSeek hosts using workspace-skill-manifest.v1 and skill-pool-manifest.v1, resolve the configured workspace registry and Skill pool from host configuration. After Skill installation run `skill register --agent sealseek --target-root ROOT --registry FILE --pool-root DIR`. This backs up the manifests, adds only this package’s records and pool link, and preserves managed UI choices. Existing unknown records are refused. Other host schemas return an explicit unsupported error. Registration files do not prove live host discovery; confirm it in the host when available.

## Startup automatic updates

`update auto status` is read-only. `update auto disable --yes` and `enable --yes` persist the user's policy outside the package; `PHOTOCRAFT_OWN_AUTO_UPDATE=0` opts out for one environment. Stable latest is the automatic channel; an explicit prerelease/manual installation is a separate decision.

Automatic checks occur before global installed launch/exec/mcp/serve operations, including Agent headless sessions. Help, version, capabilities, doctor and status do not trigger updates. Registry lookup is bounded to five seconds. Active desktop or headless sessions defer updates; concurrent startup updates serialize. Unsaved documents and running tasks are preserved. A process whose manager was replaced relaunches once through the verified new entry, preserving native exit status and protocol stdout; update diagnostics go to stderr.

The npm manager is backed up with its existing shims before replacement. The new exact version is verified through its CLI; failed replacement restores and probes the old entry. Then the new manager synchronizes its pinned runtime and existing managed Skill targets. `update sync --yes` invokes that binding/Skill synchronization explicitly. Unchanged native identities transfer zero native bytes; headless mode remains headless. Removed/unmanaged targets and local edits are preserved rather than adopted automatically. A copied Skill with local edits reports a warning, so an otherwise usable updated CLI can continue.

If a native update fails after the manager was replaced, retain the verified installed runtime and report the warning; use doctor and explicit lifecycle recovery before retrying. The supported manager/native contract must remain compatible. A successful file sync does not reload an Agent's current prompt: after a startup update, resolve `skill source`, load the current Skill and refresh command discovery for subsequent edits.
